Databases · IT · ETL

This seat is for starting from scratch. Plain language. What it is. Why you might care. One tiny try. Not a résumé flex ... a desk you can sit at when the terms feel huge.

ELI5 map · four words, one desk

Four ideas show up together a lot when people build software for real organisations. Here is the kid-version first:

  • Database ... a careful filing cabinet for facts (rows and columns), so many people can look things up without losing the papers.
  • SQL (Structured Query Language) ... the question language you use to ask that filing cabinet things like “show me every order from Tuesday.”
  • IT (information technology) / information systems ... the people + tools + processes that move information around a school, clinic, restaurant, or company so work can actually happen.
  • ETL (extract, transform, load) ... a recipe for moving data from messy places into a cleaner place: pull it out, clean/reshape it, put it where analysts or apps can use it.

You will also hear ELT (extract, load, transform) ... same ingredients, different order. Sometimes the warehouse is strong enough to clean the data after it lands.

What is a database?

What: A database stores structured data so programmes and people can find it later. Think spreadsheet energy, but built for many users, rules, and backups ... not one file that lives only on your laptop.

Why care: Almost every app you use (Handshake, Canvas, a restaurant POS) is talking to a database behind the scenes. If you want to build or fix internal tools, this is the ground floor.

Try this: Open the official PostgreSQL tutorial and read only “Getting Started” + “Creating a New Table.” Postgres (PostgreSQL) is a real open-source database people run at work ... good first friend.

What is SQL?

What: SQL (Structured Query Language) is how you talk to most relational databases. You write short commands: create a table, add a row, ask a question, update a mistake, delete something carefully.

Why care: SQL is the shared language across Postgres, MySQL, SQLite, and many warehouse tools. Learn it once ... it travels with you.

Try this: Watch the first 20 minutes of CS50 SQL · Lecture 0 · Querying (Harvard CS50 channel), or start the free CS50 SQL course site and do Week 0 only.

What is IT · what is an information system?

What: IT (information technology) is the tech stack side ... hardware, software, networks, databases, security. An information system is bigger than the box: technology plus people plus process. Example: the restaurant POS is technology; the night shift knowing how to void a ticket and who to call when the printer dies is the system.

Why care: Internal information systems are the quiet backbone ... payroll, inventory, student records, ticketing. Fancy demos fail when the handoff after the demo is messy. Systems thinking is how you keep things usable for the next person.

Try this: Read Chapter 1 of the open textbook Information Systems for Business and Beyond (“What Is an Information System?”). One chapter. Then Chapter 4 when you are ready for data + databases.

What is ETL?

What: ETL (extract, transform, load) means:

  • Extract ... pull data from somewhere (a CSV, an API, an old database, a form export).
  • Transform ... clean it (fix dates, drop junk rows, rename columns, join tables).
  • Load ... put the cleaned result into a target (another database, a warehouse, a dashboard source).

Why care: Real organisations do not live in one perfect spreadsheet. ETL (and data pipelines more broadly) is how attendance, sales, or sensor data becomes something you can trust for a report. You will also hear batch (run on a schedule, like nightly) vs stream (keep processing as events arrive).

Try this: Watch IBM Technology’s short What is ETL (Extract, Transform, Load)? (~5 min), then skim Google Cloud · What is ETL? for batch vs streaming + ETL vs ELT in plain English.

DIY path · one week of next sips

Do not binge. One sip a day beats a nine-hour panic watch.

  1. Day 1 · words only. Re-read the ELI5 map on this page. Say each acronym out loud once.
  2. Day 2 · SQL ears. CS50 SQL Lecture 0 for 20 to 40 minutes. Pause and copy one SELECT example.
  3. Day 3 · database hands. Skim the Postgres tutorial chapters on creating a table and querying. Install later if you want ... reading first is fine.
  4. Day 4 · systems brain. Open textbook Chapter 1. Write three bullets: tech / people / process for one IU system you already use (Canvas, One.IU, Handshake).
  5. Day 5 · ETL picture. IBM ETL video + Google Cloud ETL page. Draw boxes: Source → Transform → Target.
  6. Day 6 · pipeline zoom-out. ByteByteGo’s data pipeline video (~5 min). Notice batch vs stream language.
  7. Day 7 · cloud docs peek. Open one of: AWS Glue overview, Microsoft Learn ETL, or Google Dataflow overview. Read the first screen only. Goal: recognise the words, not master the product.
